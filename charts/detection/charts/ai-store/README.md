# AI Store Helm Setup

This chart deploys AI Store with optional internal MLflow, MinIO, Zot, Postgres, Redis, Dex, and OAuth2 Proxy.

The setup is based on [AI Store deployment guide](https://netreveal.atlassian.net/wiki/spaces/HARMONY/pages/1277526176/AI+Store+deployment+guide) with focus strictly on helm deployment.

## Configuration files

The chart is driven by two values files:

- `values.yaml` — the chart's default values, loaded automatically by Helm. This is the detailed, advanced-configuration base: resource requests/limits (pod sizes), liveness/readiness probes, ingress hardening (per-source-IP rate limits, response headers/CSP), the pinned versions for the mirrored public dependency images, and the full catalog of tunables with sensible defaults. You normally **do not edit this file** — treat it as the reference for every setting and its default.
- `values-scp.yaml` — the file you **fill in and pass to Helm** for a deployment. It carries only what changes per environment: namespace, ingress hostnames, image tags, feature toggles, and the secret values under `global.secrets`. Helm layers it on top of `values.yaml`, so it stays small and readable. **This is the single file to edit for a standard deployment.**

Deploy by layering the overlay on the defaults (Helm reads `values.yaml` automatically):

```bash
helm upgrade --install <release> ./helm/ai-store -n <namespace> -f helm/ai-store/values-scp.yaml
```

`values-scp.yaml` ships with `global.manageSecrets=true`, so the chart creates the Kubernetes Secret from the `global.secrets` values you fill in — no pre-created secret required. If you prefer to keep credentials in a separate, gitignored overlay, split them out and pass it as an extra `-f` (see the header comment in `values-scp.yaml`); either way, **never commit real credentials**.

## Prerequisites

- Push all application images referenced in `values-scp.yaml` to your container registry before deploy.
- Create/update the image pull secret referenced by `global.imagePullSecrets` (for example, `<image_pull_secret_name>`) in the target namespace so the cluster can pull those images.
- Configure DNS for ingress hosts using one of these approaches:
  - wildcard record for your domain (for example, `*.example.com`) pointing to the ingress controller address
  - separate records per host used by this chart:
    - `domain.modelhubHost`
    - `domain.mcpHost`
    - `domain.mlflowHost`
    - `domain.minioHost`
    - `domain.zotRegistryHost`



## Dependency charts (vendored locally)

The third-party subcharts — **mlflow**, **minio**, **zot** — are vendored as local
`file://` source directories (`helm/ai-store/{mlflow,minio,zot}/`), exactly like the
in-house `model_training_tool` / `monitoring_tool` subcharts. `Chart.yaml` points at
`file://./<name>`, so `helm dependency build` **and** `helm dependency update` **are fully
offline and never fetch from public Helm repos**. Rendering (`helm template` / `helm install`) uses the packaged tarballs in `charts/` directly.

To upgrade a dependency chart: replace its unpacked directory with the newer chart source,
bump the `version:` in `Chart.yaml`, then run `make helm-deps` (or
`helm dependency update helm/ai-store`) to regenerate `Chart.lock` and repackage
`charts/*.tgz`.

## Public image mirroring to ACR

All **public** container images the chart pulls (postgres, redis, dex, alpine,
oauth2-proxy, and the mlflow/minio/mc/zot/busybox images from the dependency charts,
plus docker:dind and celery-exporter) are mirrored into the ACR under the
`ai-store-services/` repository so deployments do not depend on Docker Hub / quay.io /
ghcr.io at pull time.

These are defined **once, in** `values.yaml` at their `ai-store-services/`* ACR paths with
pinned versions (they rarely change), so `values-scp.yaml` inherits them and carries no
per-image overrides. oauth2-proxy is pinned to `v7.15.3`; the zot bootstrap Jobs use
`zotBootstrap.image`. To consume a different registry, override the `repository` in
`values-scp.yaml`.

**First-party** app images (backend/frontend/mcp-server/training/monitoring) default to tag
`latest` with `pullPolicy: Always` and `global.rolloutOnHelmUpgrade: true` — the Build
pipeline always pushes/overwrites `:latest`, so chart values need no per-release tag bumps.
Pin a specific build at deploy with `--set backend.image.tag=<tag>` (etc.) if required.

- Authoritative image list: `[pipelines/mirror/acr-mirror-manifest.yaml](../../pipelines/mirror/acr-mirror-manifest.yaml)`
- Mirror tool: `[pipelines/scripts/acr-mirror.sh](../../pipelines/scripts/acr-mirror.sh)` —
idempotent `az acr import` (skips tags that already exist). Run locally with
`az login && ACR_NAME=<registry-short-name> make acr-mirror` (`DRY_RUN=1` to preview).
- In CI it runs as the **MirrorDependencies** stage (automatic on every non-PR build in
`azure-pipelines.yml`; opt-in via the `runAcrMirror` parameter in
`azure-pipelines-manual.yml`).

## Filling in `values-scp.yaml`

`values-scp.yaml` ships sanitized — every environment- and deployment-specific value is an
empty string or `<placeholder>` ready to be filled in. Use it directly as your template:

1. Set the namespace (`namespaceOverride`) and ingress hostnames (`domain.*`).
2. Set the first-party image tags (`backend`/`frontend`/`mcpServer`/`model_training_tool`/
  `monitoring_tool`), or leave them at `latest` and pin per deploy with `--set`.
3. Toggle features (`internalServices.*`, `dex`, `oauth2Proxy`, `model_training_tool`,
  `monitoring_tool`, `hpa`).
4. Fill the credentials under `global.secrets` and `internalServices.secrets`.

The tables above document every key and when it is required. Anything not overridden here
falls back to the tuned defaults in `values.yaml` (resources/pod sizes, probes, mirrored
image versions, ingress hardening) — so you only edit what actually differs per environment.

For credentials, either fill them in place and keep the file out of git, or move
`global.secrets` / `internalServices.secrets` into a separate gitignored overlay and pass it
as an extra `-f` (see the header comment in `values-scp.yaml`).

## Deploy commands

Helm loads `values.yaml` automatically; you only pass the filled-in `values-scp.yaml`.

### Chart-managed secrets (`global.manageSecrets=true`, the default)

```bash
helm dependency update ./helm/ai-store

helm upgrade --install <release-name> ./helm/ai-store \
  -n <namespace> \
  -f helm/ai-store/values-scp.yaml
```

If you keep credentials in a separate gitignored overlay, add it as another `-f`:

```bash
helm upgrade --install <release-name> ./helm/ai-store \
  -n <namespace> \
  -f helm/ai-store/values-scp.yaml \
  -f helm/ai-store/values-scp.secrets.yaml
```



### Pre-created cluster secret (`global.manageSecrets=false`)

Set `global.manageSecrets: false` in `values-scp.yaml` and use this only if the Secret named
by `global.secretName` already exists in the namespace with every required key.

```bash
helm dependency update ./helm/ai-store

helm upgrade --install <release-name> ./helm/ai-store \
  -n <namespace> \
  -f helm/ai-store/values-scp.yaml
```

### 1.2 Promotion boundary (verified)

Separate repository names inside the shared `symphonyfs` registry are **not** sufficient:
`deploy-fe-be-prod-basic.yml` accepts free-form `backend_image` / `frontend_image` references and does not validate the
repository, so a manual dispatch could put any `symphonyfs` image on the production apps. The production apps' managed
identities hold `AcrPull` only on `rg-cfe-apps-mj`, `production-devops` (which contains `symphonyfs`) and three named
registries.

Therefore the E2E images go to a **separate registry inside `rg-cloudhub-e2e`**. Production cannot pull from it (no
role assignment, no credentials), so no existing workflow — staging deploy, promotion swap, rollback or direct deploy —
can run an E2E image on production. Optional hardening (not done; changes production tooling): validate the repository
in `deploy-fe-be-prod-basic.yml`.

### 1.5 Build and deployment commands (to run only after explicit authorization)

Prerequisites: Contributor on the subscription (creating the RG and resources — the current user has it); **no** role
assignment rights are needed because the apps pull with the test registry's admin credential instead of `AcrPull`;
an Entra **Application Administrator** for the two app registrations and a **Privileged Role Administrator / Global
Administrator** for Graph admin consent and the Tenant Root Group Reader assignment.

```bash
SUB=b0799078-b42a-4b59-9e70-22cd09a20ee2; RG=rg-cloudhub-e2e; LOC=swedencentral; ACR=cloudhube2eacr
TAG="e2e-$(git rev-parse --short HEAD)-1"     # record `git diff --stat` alongside the tag

# 1. Infrastructure (no images yet)
az group create -n $RG -l $LOC --subscription $SUB --tags purpose=cloudhub-e2e expires=<yyyy-mm-dd>
az acr create -g $RG -n $ACR --sku Basic --admin-enabled true
az appservice plan create -g $RG -n asp-cloudhub-e2e --is-linux --sku B2
az webapp create -g $RG -p asp-cloudhub-e2e -n cloudhub-e2e-backend  --container-image-name mcr.microsoft.com/appsvc/staticsite:latest
az webapp create -g $RG -p asp-cloudhub-e2e -n cloudhub-e2e-frontend --container-image-name mcr.microsoft.com/appsvc/staticsite:latest
az webapp update -g $RG -n cloudhub-e2e-backend  --https-only true
az webapp update -g $RG -n cloudhub-e2e-frontend --https-only true
BACKEND_HOST=$(az webapp show -g $RG -n cloudhub-e2e-backend  --query defaultHostName -o tsv)
FRONTEND_HOST=$(az webapp show -g $RG -n cloudhub-e2e-frontend --query defaultHostName -o tsv)   # may be a randomized hostname
az postgres flexible-server create -g $RG -n cloudhub-e2e-pg -l $LOC --tier Burstable --sku-name Standard_B1ms \
  --version 16 --storage-size 32 --high-availability Disabled --public-access None \
  --admin-user cloudhub_e2e --admin-password "<from secret store>"
for ip in $(az webapp show -g $RG -n cloudhub-e2e-backend --query possibleOutboundIpAddresses -o tsv | tr ',' ' '); do
  az postgres flexible-server firewall-rule create -g $RG --server-name cloudhub-e2e-pg --name "be-${ip//./-}" \
    --start-ip-address $ip --end-ip-address $ip
done

# 2. Images (from the working tree; the frontend needs the real hostname)
az acr login -n $ACR
docker build -f docker/Dockerfile.backend --build-arg CLOUDHUB_VERSION=$TAG -t $ACR.azurecr.io/cloudhub/backend:$TAG .
docker build -f docker/Dockerfile.frontend --build-arg APP_BASE_URL=https://$FRONTEND_HOST \
  --build-arg BACKEND_BASE_URL=https://$FRONTEND_HOST --build-arg AUTH_ENVIRONMENT=production \
  --build-arg CLOUDHUB_VERSION=$TAG -t $ACR.azurecr.io/cloudhub/frontend:$TAG .
docker push $ACR.azurecr.io/cloudhub/backend:$TAG; docker push $ACR.azurecr.io/cloudhub/frontend:$TAG

# 3. Settings (names in §1.6; values piped from the secret store, never echoed), then images
az webapp config appsettings set -g $RG -n cloudhub-e2e-backend  --settings @backend-settings.json   # file outside the repo, deleted after use
az webapp config appsettings set -g $RG -n cloudhub-e2e-frontend --settings BACKEND_ORIGIN=https://$BACKEND_HOST WEBSITES_PORT=80
az webapp config container set -g $RG -n cloudhub-e2e-backend  --container-image-name $ACR.azurecr.io/cloudhub/backend:$TAG \
  --container-registry-url https://$ACR.azurecr.io --container-registry-user $ACR --container-registry-password "<acr admin password>"
az webapp config container set -g $RG -n cloudhub-e2e-frontend --container-image-name $ACR.azurecr.io/cloudhub/frontend:$TAG \
  --container-registry-url https://$ACR.azurecr.io --container-registry-user $ACR --container-registry-password "<acr admin password>"
az webapp config set -g $RG -n cloudhub-e2e-backend --always-on true --generic-configurations '{"healthCheckPath":"/.backstage/health/v1/readiness"}'
az webapp restart -g $RG -n cloudhub-e2e-backend; az webapp restart -g $RG -n cloudhub-e2e-frontend

# 4. Verify (§1.7), then the access checklist (§2)
bash scripts/release/backend-smoke-test.sh  https://$BACKEND_HOST
bash scripts/release/frontend-smoke-test.sh https://$FRONTEND_HOST
```
